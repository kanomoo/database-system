คราวนี้ นะคะ ตัว สังเกตได้ว่า นักศึกษาสังเกตดูนะ ตรงนี้ เป็น ตัวอย่าง ของตาราง 2 Dog เนาะ มี ID, มี Name, มี Mood, มี Birthday แล้วก็มี Color เห็นมั้ยคะ ตรงตาม Dog เลย นะคะ ถัดมา นะคะ สังเกตได้ว่า ตัว Bark เชื่อมโยงกับ Dog ถูกมั้ยคะ เห็น Bark มั้ยคะ เชื่อมโยงกับ Dog เป็น เชื่อมโยงผ่านอะไรคะ ID ID ใน ในตัว Dog คือ ID ในตัว Bark นี่คือ เชื่อมโยงกับ Attribute ไหนคะ Dog ID เนาะ สังเกตได้ว่า เค้าเขียนชื่อ ในนักศึกษาดูนะ ตรง Dog เนี่ย นะคะ มี Primary Key เป็น ID Bark ก็มี Primary Key เป็น ID เห็นมั้ย เห็นมั้ย ชื่อซ้ำเห็นมั้ย แล้วก็ Comment ก็มี ID เป็น Primary Key ซ้ำกันมั้ย พอเราจะเขียนการเชื่อมโยง PK FK ปุ๊บ เกิดปัญหาขึ้นละ ถ้าเราไปใส่ ID ทั้งคู่ บอกแล้วว่า Attribute ชื่อ เป็นไงคะ ชื่อ Attribute ต้องไม่ซ้ำ พอไม่ซ้ำปุ๊บ ในเมื่อคุณกำหนดให้ ID ตรง Bark เนี่ย เป็น ID ที่เป็น PK เพราะฉะนั้น ตัว FK ตัว FK ของ Dog มา ที่เป็น ID เหมือนกัน คุณจะต้องให้ชื่อว่าเป็น Dog ID เพื่อบอกว่า เป็น เป็น FK ในตาราง Bark ซึ่งไปเป็น PK ในตาราง Dog นั่นเอง นะคะ เพราะฉะนั้น เวลาที่นักศึกษาเขียน นักศึกษาควรจะเขียน อ่า ชื่อ Attribute ที่สื่อ นิดนึง ใน Dog ก็ควรจะเขียนเป็น Dog ID ถูกมั้ย อ่า ใน Bark ก็เขียนเป็น Bark ID Comment ก็เขียนเป็น Comment ID เนาะ อ่า แล้วให้สังเกต นะคะ ในตัว Bark กับตัว Comment มีการเชื่อมโยงกัน เห็นมั้ย อ่า พอเชื่อมโยงกันปุ๊บ ให้สังเกตว่า จาก ID ของ Bark มาเป็น FK ตรงนี้เขียนว่า Bark ID ละ เห็นมั้ยคะ เพื่อสื่อถึงการเชื่อมโยง ตรงนี้เชื่อมโยงกับ Dog ด้วย Dog ID เห็นมั้ยคะ เคย์นะ อันนี้ก็คือ เป็นลักษณะ ที่เค้ายกตัวอย่าง RDBMS นั่นเอง ที่มี PK FK นะคะ ใน Comment เนี่ย ที่เป็น PK ก็คือ ID เนาะ ที่เป็น FK ก็คือ ตัว Bark ID กับ Dog ID นะคะ เค้าต้องการสื่อ นะคะ ว่า RDBMS เนี่ย นะคะ มี การสร้างตารางที่มีความเชื่อมโยงกัน นะคะ

คราวนี้ ถัดมา เรามาดูอันนี้นะคะ ตรง ที่เป็น นะคะ เค้าบอกว่า อ่า ทำไมเราจึงจำเป็นต้องมี ตัว NoSQL เนื่องมาจากว่า Relational Database เนี่ย นะคะ เกิดปัญหาขึ้น นะคะ สำหรับ นะคะ ฐานข้อมูล ที่เป็นฐานข้อมูลเชิงสัมพันธ์ หรือที่เราเรียกว่า Relational Database เนี่ย นะคะ ถ้าเกิดว่า พอเรา นะคะ มีการใช้ทรัพยากรของเครื่อง นะคะ ที่ไม่เพียงพอแล้ว เนี่ย นะคะ เวลาที่ ตัว RDBMS เนี่ยค่ะ เค้าทำการถูกออกแบบมา ให้เหมาะ กับการใช้ ตัว Server ที่เครื่องเครื่องเดียว ไม่ได้เหมาะ กับการ ที่ กระจายข้อมูล ไปหลายๆ เครื่อง คือในการออกแบบตั้งแต่ครั้งแรกเลยของเค้า เนี่ย นะคะ เค้าถูกออกแบบมาให้เหมาะกับใช้กับเครื่อง เครื่องเดียวเท่านั้น นะคะ แต่ถามว่า แล้วเรากระจาย ข้อมูลไปหลายๆ เครื่องได้มั้ย ได้ ได้นะคะ แต่จะอาจจะทำให้ประสิทธิภาพ ในการทำงานนั้น ลดลง อันนี้ ก็คือ นะคะ ข้อมูล นะคะ ที่เค้าบอกว่า มันเกิดปัญหานี้นั่นเอง นะคะ ถ้าเกิดว่า ข้อมูล อยู่ภายในเครื่องเครื่องเดียว ที่เรามีการสร้าง Table เราทำ Normalize Table แล้วมี PK FK อยู่ในเครื่องเครื่องเดียวเนี่ย สามารถจัดการได้ง่ายเลย นะคะ ไม่มีปัญหา เห็นมั้ยคะว่ายิ้มเลย นะคะ เป็นรูปยิ้มเนาะ ถัดมา ถ้าเกิดว่า นะคะ ไอ้ตัวนี้ นะคะ มีการ กระจายข้อมูล ไปหลายๆ เครื่อง นะคะ ไปหลายๆ เครื่อง นะคะ สังเกตได้ว่า ตรงเนี้ย SQL ที่ทำงานกับคำสั่งเนี่ย เค้า Sad ก็คือ เศร้าเลย เพราะว่า มันทำงานได้ยาก นะคะ

เกิดจากอะไรล่ะ เกิดจาก นะคะ เพราะว่า อันแรกเลย เห็นมั้ยคะว่า Join Are Expensive ก็คือ การ Join เนี่ย นะคะ มันทำได้ยุ่งยาก เค้าเปรียบเทียบด้วยว่า มัน Expensive นะคะ เพราะอะไร เพราะว่า ถ้าเกิดว่า เรามีการสร้างฐานข้อมูล แล้วก็มี ตาราง ที่เรา Normalize แล้ว เราสร้าง PK FK เรียบร้อยแล้ว อยู่ในฐานข้อมูลเดียว เวลาเราทำการ Join เราไม่ต้องข้ามเครื่องไปไหน เราเรียกข้อมูลในนี้ ซึ่งตัว Server รู้อยู่แล้ว ว่าข้อมูลอยู่ตรงไหน ไม่มีปัญหา Join ได้ง่าย สามารถทำงานได้อย่างรวดเร็ว แต่ถ้าเกิดว่า เรามีการ ข้อมูลเยอะ แล้วเราแบ่งไปหลายๆ เครื่อง หลายๆ Server สมมุตินะ เราแบ่งไปหลายๆ Server อย่างเงี้ย เค้าต้องรู้ก่อนว่า ข้อมูลแต่ละข้อมูล เก็บอยู่ที่ Server ไหน นั่นเอง แล้วในการทำ PK FK ถูกมั้ยคะ ทำการ Join เนี่ย นะคะ ดึงจาก ข้อมูลจาก Server แต่ละ Server มาเนี่ย มันใช้ระยะเวลา นะคะ มันใช้ระยะเวลา เพราะฉะนั้น เค้าก็เลยบอกว่า มัน Join Are Expensive นั่นเอง

ถัดมา นะคะ Hard to Scale ก็เป็นไปได้ยากค่ะ เพราะว่าอะไรคะ เพราะว่า เรา เวลาที่ทำงานน่ะค่ะ ถ้าเก็บไว้ใน Server เดียว ดีกว่า มันก็จะเก็บไว้ในก้อนเดียว แต่คราวนี้ ถ้าเกิดเรามี การ มีหลายๆ Server เราต้องแบ่ง ตัวข้อมูล อะค่ะ ตารางนึง อาจจะมีเป็น 10 ล้าน Record ถูกมั้ยคะ เก็บไว้ในเครื่องเดียวไม่พอ เค้าจะต้องมีการแบ่ง ตัวข้อมูล ไปในแต่ละเครื่อง แบ่งไม่พอ แล้วตารางนั้น เชื่อมโยงกับ PK FK ตัวไหนล่ะ เค้าจะต้องมีการ จัดการ เพราะฉะนั้น มันยาก ในต่อการจัดการ นะคะ Hard to Scale นะ

ถัดมา นะคะ Impedance Mismatch Occur ตัวนี้ เราจะหมายความว่า เวลาที่เราเขียนโปรแกรม ในปัจจุบัน เนี่ย โดยส่วนใหญ่แล้ว เนี่ย เป็นลักษณะเชิง Object-Oriented เนาะ เป็น OO แต่ว่า เวลาที่เราเก็บข้อมูล ที่เป็นตาราง น่ะ เป็น Row กับ Column เวลาที่เราเก็บ ใช่ไหม คราวนี้ พอเราเขียน โปรแกรมเป็น OO เค้าต้องมีการแปลง ไปอยู่ในรูปแบบ ของ ตาราง เพื่อที่จะทำการเก็บ นะคะ แล้วพอดึงข้อมูล จากตารางออกมา ก็ต้องแปลงไปในรูปแบบของ Object เพื่อใช้งาน ในตัวแอปพลิเคชัน นะคะ

ถัดมา นะคะ Expensive นะคะ ตัวนี้จะหมายความว่า นะคะ ค่าใช้จ่ายแพง ไม่ว่าจะเป็นค่า ลิขสิทธิ์ซอฟต์แวร์ ที่ใช้งาน นะคะ ตัวฮาร์ดแวร์ ต้องมีประสิทธิภาพสูงๆ นะคะ แล้วก็ รวมไปถึงการ Maintenance นะคะ รวมไปถึงตัว DBA ที่เราทำการจ้างมา เพราะว่า ระบบมีความซับซ้อนมาก เค้าต้องใช้ DBA ในการจัดการ ให้ นะคะ เกิดค่าใช้จ่าย เหล่านี้ นะคะ

ถัดมา นะคะ ซึ่ง นะคะ ตรงเนี้ย ถ้าเรา มีการ กระจายข้อมูล ไปไว้หลายๆ Server ที่เรียกว่า Distributed Application เนี่ย นะคะ จะทำให้ Weak ก็คือ มีข้อเสีย หรือว่า มัน อ่า ทำงาน ได้ไม่เต็มประสิทธิภาพ ตามนี้ นะคะ ก็คือทำให้มันอ่อนแอ นั่นเอง
- ความเร็วลดลง ใช่ เพราะเราแบ่งปุ๊บ ใน เราต้องทำการ Join ข้อมูลแต่ละ Table ผ่านเครือข่าย ความเร็วลดลงแน่นอน
- High Availability คือ ความพร้อมใช้งาน ตลอดเวลา ก็อาจจะลดลง เช่น ถ้ามีโหนด โหนดใดโหนดหนึ่งเสีย หรือว่า อ่า เครือข่าย เกิด เสียหาย ไม่สามารถทำงานได้ แน่นอน ฟัง ตรง High Availability ตัวนี้ ก็จะทำให้ ไม่สามารถใช้งานได้ ตลอดเวลา
- Partition Tolerance ก็คือ เครือข่าย เกิดการเสียหาย นะคะ ไม่สามารถที่ จะ นะคะ อ่า ส่งข้อมูลระหว่างเครือข่ายได้ นะคะ

ถัดมา นะคะ คราวนี้ NoSQL ตอบโจทย์อะไรบ้าง นะคะ เรามาดูนะ ต้องบอกก่อนว่า ในปัจจุบัน เนี่ย นะคะ ข้อมูล อะ เกิดขึ้นเยอะมาก นะคะ เพราะฉะนั้น การจะเก็บข้อมูลไว้ในเครื่องเครื่องเดียว แล้วไปใช้งานเนี่ย มันเป็นไปได้ยาก เนาะ มันอาจจะต้องมี การทำ เป็นลักษณะ Distributed Application อย่างเมื่อกี้ ก็คือ มีการจัด กระจาย ข้อมูลไปหลายๆ หลายๆ เครื่อง นะคะ ซึ่งตัว NoSQL ก็จะตอบโจทย์ ตรงนี้นะคะ

เรามาดูนะคะ อันแรกเลย คือ Big Data Big Data นะคะ ก็คือ ข้อมูลนั้น มีปริมาณ จำนวนเยอะ ในระดับหน่วย Terabyte นะคะ อ่า แล้วข้อมูลนั้น นะคะ มีความรวดเร็วในการเปลี่ยนแปลง เกิดขึ้น อย่างรวดเร็ว เปลี่ยนแปลงอย่างรวดเร็ว ก็คือเจริญเติบโตขึ้นอย่างรวดเร็ว นั่นเอง ข้อมูลนั้น นะคะ แล้วก็ ข้อมูลนั้น นะคะ จะต้องมีความหลากหลาย หลากหลายของโครงสร้าง นะคะ เช่น อาจจะเป็นลักษณะของ Structured, Semi-structured แล้วก็ Unstructured ด้วย นะคะ ซึ่ง ข้อมูลที่เป็นโครงสร้าง เป็นยังไง ข้อมูลที่เป็นโครงสร้าง ก็เช่น ข้อมูลที่ นะคะ เราสามารถทำในรูปแบบของ RDBMS ได้นั่นเอง ในรูปแบบของตาราง สามารถนำข้อมูลไปใส่ในรูปแบบของตาราง ว่าประกอบไปด้วย Attribute อะไรบ้าง อันนั้นคือ ข้อมูลมีโครงสร้าง

ถัดมา นะคะ ข้อมูลที่เป็น Semi-structured ก็คือ ข้อมูล กึ่งโครงสร้าง นะคะ ตัวนี้ จะหมายถึง ตัวพวกไฟล์ ที่เป็นลักษณะของ XML หรือ JSON ที่ใช้ นะคะ ส่วนข้อมูลที่เป็น Unstructured ก็เช่น ข้อมูลที่ ไม่มีโครงสร้างเนาะ เราไม่สามารถ จัดข้อมูลเนี่ย ให้อยู่ในรูปแบบของโครงสร้างได้ นะคะ เช่น ข้อมูลที่เป็นเสียง ไฟล์ภาพ หรือแชตข้อความ เป็นต้น เหล่านี้ นะคะ
