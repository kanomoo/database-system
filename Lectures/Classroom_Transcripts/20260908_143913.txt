ข้อที่ 1: คุณสมบัติ ACID Properties ของ Transaction
- Atomicity: ทำทั้งหมดหรือยกเลิกทั้งหมด (All or Nothing) ห้ามทำค้างคา หากผิดพลาดต้อง Rollback
- Consistency: ฐานข้อมูลต้องเปลี่ยนจากสถานะที่ถูกต้องหนึ่งไปสู่อีกสถานะที่ถูกต้องหนึ่งตามเงื่อนไขทางธุรกิจ
- Isolation: Transaction แต่ละรายการทำงานแยกกันอย่างอิสระ ไม่เปิดเผยข้อมูลระหว่างทำให้คนอื่นเห็น
- Durability: เมื่อมีคำสั่ง COMMIT ข้อมูลจะถูกบันทึกลง Hard Disk อย่างถาวร ไม่สูญหายแม้ไฟดับ

ข้อที่ 2: Lock-based Concurrency Matrix และ Crash Recovery
1. ตาราง Lock Matrix:
   - S-Lock (Shared / Read) อนุญาตให้อ่านพร้อมกันได้ ดังนั้น (S, S) = YES
   - X-Lock (Exclusive / Write) ต้องการแก้ไขข้อมูลเพียงผู้เดียว ดังนั้น (S, X), (X, S), (X, X) = NO ทั้งหมด
2. การจัดการ 5 Transactions ใน Log File หลังเซิร์ฟเวอร์ Crash:
   - Transaction ที่มีบันทึก COMMIT ก่อน Crash -> DBMS จะสั่ง "REDO" (นำค่าใหม่เขียนลง Disk)
   - Transaction ที่มีคำสั่ง START แต่ยังไม่มี COMMIT ตอน Crash -> DBMS จะสั่ง "UNDO / ROLLBACK" (นำค่าเดิมกลับมาแทนที่)
